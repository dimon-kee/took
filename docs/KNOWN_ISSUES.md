# 已知问题

只记还没解决的。解决了就删掉，不留「已修复」。

## 录屏卡片的选项不跟着换屏幕

- **现象**：在屏幕 A 选好区域，在录屏卡片上开了麦克风、摄像头或改成 GIF，再到屏幕 B 单击重新选区，B 的卡片还是默认选项。截图 / 长截图 / 录屏 / 文字这几个模式已经会跟到另一块屏幕，卡片里的选项还不会。
- **影响**：多屏时换了屏幕要重新设一遍。
- **发现**：2026-11-17
- **打算**：和模式一样，经主进程把 `S.rec` 同步给其他屏幕的取景层。

## 选区下沿贴近任务栏时，选画图工具会让工具栏跳到选区上方

- **现象**：选区下沿落在任务栏上方大约 40px 的范围里时，下面放得下工具栏，但放不下工具栏加颜色栏。点矩形等画图工具后，两条一起翻到选区上方。
- **影响**：刚点的按钮从指针底下跑开。
- **发现**：2026-11-17，修颜色栏压住工具栏时注意到的，是原来就有的行为。
- **绕过**：按住工具栏左边的 ⋮⋮ 把它拖到别处，之后它就不会再跟着选区移动。
- **打算**：工具栏的位置只按它自己定，颜色栏放到有空间的那一侧。

## 直接保存的提示靠 Windows 通知，通知关了就看不到

- **现象**：「保存时」选「直接存进这个文件夹」后，截图（包括长截图、贴图）存好了，只靠托盘弹出的 Windows 通知说存到了哪里——取景层存完马上就关了，没有别的地方能显示。在 Windows 设置里关掉了 Took 的通知，或者开着「请勿打扰」/专注助手时，存完屏幕上什么都不出现。
- **影响**：文件照常存好，只是没有反馈。可能以为没存上又存一次，结果多出一个 `(2)`（不会覆盖）。录屏不受影响：编辑窗口会提示「已保存」，并在资源管理器里显示文件。
- **发现**：2026-11-17
- **绕过**：设置里点「打开」看保存位置；或者改成「每次都问存到哪里」。
- **打算**：真成了问题的话，在取景层关掉之后，在屏幕角落显示一个不抢焦点、几秒后自己消失的小窗口。

## 托盘通知共用一个点击动作，点旧的那条可能做了新那条的事

- **现象**：托盘的通知（`balloon()`）只有一个点击回调，总是最后一条通知的。Windows 的托盘通知点了也不说是哪一条。所以「截图已保存」的通知还在屏幕上、紧接着又弹出「Took x.y.z 已准备好」时，点那条截图通知会重启 Took 去装更新；反过来，点旧的更新通知会打开截图所在的文件夹。
- **影响**：要碰巧两条通知同时在屏幕上（或在通知中心里点旧的那条）。最坏是更新提前装上、Took 重启一次。
- **发现**：2026-11-17
- **为什么没修**：review 建议在 `balloon-closed` 时清掉回调。可这管不了两条同时在屏幕上的情况，而且旧通知超时后发来的 `balloon-closed` 可能把新通知的回调清掉，连拍两张时第二条点了就没反应了。
- **打算**：改用 Electron 的 `Notification`，每条通知有自己的 click 事件。先要确认开发版（没有开始菜单快捷方式）下它能弹出来。

## 保存位置在掉线的网络盘上时，保存会让 Took 卡几秒

- **现象**：`saveDir()` 的 `mkdirSync` 和「每次都问」时 `dialogDir()` 的 `statSync` 都是同步的。文件夹在一个连不上的网络盘上时，它们要等到网络超时才返回，主进程这几秒什么都不响应。
- **影响**：按保存后取景层定住几秒，然后照常退回 `图片/Took` 或弹出对话框。`saveDir()` 这个问题以前就有。
- **发现**：2026-11-17
- **打算**：改用 `fs.promises` 在后台线程检查，`saving.js` 的流程本来就是 async 的。
